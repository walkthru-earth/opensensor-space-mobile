# History host measurements on 2026-10-11

Branch `yharby/m-63-mi` for mobile #63. These measurements use a generated UTC day
of 8,640 rows, 96 files and seven numeric columns. The before aggregator and daily
builder are the frozen pre-change golden oracle. Both chart readers use the
current implementation with different source choices. No phone archive was read.

Apple M4, macOS 26.6.2, Android Studio bundled JBR 25.0.2, JMH 1.37 through
kotlinx-benchmark 0.5.0. One fork, three one-second warmups and five one-second
measurement iterations per operation. The GC profiler reports allocated bytes,
not object counts. Each operation processes the same 8,640 source rows.

| Operation | ns per row | JMH error per row | allocated bytes per row |
| --- | ---: | ---: | ---: |
| aggregatorAfter | 573.30 | 385.20 | 377.14 |
| aggregatorBefore | 3967.73 | 5312.47 | 740.72 |
| dailyAfter | 1100.74 | 1049.76 | 1143.50 |
| dailyBefore | 1194.70 | 308.32 | 1257.37 |
| deriveAfter | 1784.00 | 3429.02 | 1192.26 |
| deriveBefore | 2948.02 | 3336.07 | 2000.00 |
| fromDerived | 364.66 | 364.89 | 331.36 |
| fromRaw | 312.82 | 127.17 | 569.54 |

The short timing run was noisy on a shared host. Its confidence intervals overlap,
so it does not establish a latency improvement. The full-day derived scan was
slower than raw reads in this small, in-memory corpus. Its allocation rate per row
was lower. The combined single pass allocated about 40 percent fewer bytes per
row than the two passes. The allocation measurement does not establish native
allocations, phone CPU time, energy use or real archive cold-open latency.

[Raw JMH JSON](../../tools/history-benchmark/results/2026-10-11.json) retains the
scores and intervals. [Harness and commands](../../tools/history-benchmark/README.md)
describe reproduction. The reader setup asserts identical raw and derived series
before any timed operation.

The full mobile gate and native checks are recorded in the PR. Android Perfetto
on a 200-file sync, Android Microbenchmark on 30 real days, and cold History open
with about 1,000 receipts on an iPhone remain separate owner-run measurements.
